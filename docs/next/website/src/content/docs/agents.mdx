Flockr is built for running more than one coding agent at a time. Each agent stays in a real terminal pane with its shell, logs, prompts, and running processes intact. Flockr tracks which panes contain agents, rolls their state up to tabs and workspaces, and lets you jump straight to the pane that needs attention instead of polling every terminal by hand.

To coordinate agents from scripts or from another agent, see [Agent automation](/docs/agent-automation/).

## Supported agents

Agents get Flockr support in one of two ways: Flockr supports them, or they support Flockr themselves. Either way you see each agent's `idle`, `working`, and `blocked` state, get notified when it finishes or needs you, and can wait on it from scripts.

Other agents still run normally in Flockr panes. They just show up as plain terminals.

## How status works

For agents Flockr supports, Flockr finds the agent's process in each pane and reads the live bottom of the pane, not the part you scrolled to. Rules in a detection manifest decide whether that screen means `idle`, `working`, or `blocked`. When an integration also reports state, Flockr uses those reports instead of reading the screen.

For agents that support Flockr, the agent's own reports decide the state.

## VMs and sandbox wrappers

On Linux and macOS, a host-visible wrapper can hide the real agent process from Flockr. Set `FLOCKR_AGENT=<agent>` on the wrapper command to tell Flockr which existing agent screen manifest to use. For example, run `FLOCKR_AGENT=claude fence -- claude` on Linux or `FLOCKR_AGENT=claude nono run --profile claude-code -- claude` on macOS. The hint applies only to that foreground process. Flockr cannot see it if you set it only inside a VM or container. Avoid exporting it globally unless every inherited foreground process should be treated as that agent.

Some restricted Linux runtimes do not expose a terminal foreground process group. Start the Flockr server with `FLOCKR_PROCESS_DETECTION=child-groups` to opt into direct child-process-group inference when native detection is unavailable. Native detection remains preferred, and the default `native` mode never performs this inference. The opt-in mode is best effort: a newer background job can be mistaken for the foreground job. The variable is read by the server and requires a restart; set it in the remote server environment rather than on an attaching client.

## Blocked state

Blocked detection is deliberately strict for screen-manifest agents. Flockr only marks `blocked` when the live bottom-buffer snapshot matches known visible approval, question, or permission UI. If no manifest rule matches for a known agent, Flockr falls back to `idle` and labels that fallback as `default_known_agent_idle_fallback` in explain output.

Unusual new agent prompts may initially show as `idle` instead of `blocked` until Flockr learns that screen shape. Detection itself does not send input, but automation that trusts a mistaken idle state can type into an approval dialog. Inspect unexpected prompts before sending more input; idle status is not authorization to approve an action.

Antigravity and Grok count as idle once they return to their prompt, even if background tasks, monitors, or subagents are still running. `agent wait` and `agent prompt --wait` observe the agent's state, not completion of those jobs.

Suspending an agent with Ctrl+Z preserves its name, session reference, and hook authority while the exact process remains alive behind the shell or another non-agent command. Returning with `fg` keeps that identity. This does not cover another recognized agent taking over the foreground. A retained identity does not mean the agent can receive input while suspended; inspect the pane before prompting it.

## Detection manifests

Bundled manifests live inside Flockr. Flockr also checks github.com/Rambarani/flockr for remote manifest updates and applies valid per-agent rule updates automatically without requiring a Flockr restart. Remote manifests are stored in Flockr's state directory. Set `[update] manifest_check = false` to disable background remote manifest checks.

Local overrides can replace a remote or bundled manifest from the platform config directory:

```text
~/.config/flockr/agent-detection/<agent>.toml
```

Local overrides always win. Without a local override, Flockr uses the newer compatible manifest between the cached remote manifest and the bundled manifest in the running binary. On debug builds, the same config helper may use a development directory such as `flockr-dev`. Invalid override files are ignored with a warning and Flockr falls back to the cached remote or bundled manifest for that agent.

Remote manifests patch detection rules for agents Flockr already knows how to identify. Adding a completely new agent still requires a Flockr binary update for process detection, labels, and integration behavior.

The running server loads active manifests into memory on startup. Automatic remote manifest updates reload that in-memory cache after new rules are written. Run `flockr server update-agent-manifests` to fetch remote manifest updates immediately and reload the running server. After editing a local override manually, restart Flockr or run `flockr server reload-agent-manifests` to apply the file to the running server.

Use `flockr agent explain` when a pane shows the wrong state:

```bash
flockr agent explain <target>
flockr agent explain --file screen.txt --agent codex --json
```

Live explain is evaluated by the running server, so it reflects the active manifest cache. The explain output shows the agent, final state, whether screen detection was skipped by a full lifecycle authority, manifest source and version, cached remote version, local override shadowing, remote update status, matched rule, visible evidence flags, matcher and region evidence for evaluated rules, skipped-update reason for transcript viewers, and the idle fallback reason when no rule matched.

Flockr can run inside tmux as the outer terminal environment. Agent detection does not inspect tmux sessions launched inside a Flockr pane. If a shell framework auto-enters tmux inside Flockr, Flockr sees `tmux` as the pane process instead of the agent behind it.

If your shell automatically attaches to tmux whenever `TMUX` is unset, update its startup rule to exclude Flockr panes. Reattaching the outer tmux session from inside a Flockr pane can recursively shrink the terminal and make it flicker. Add the `FLOCKR_ENV` check to your existing condition before it runs tmux:

```zsh
if [[ -z ${TMUX:-} && ${FLOCKR_ENV:-} != 1 ]]; then
  tmux new-session -A -s my-session
fi
```

## State rollups

The sidebar rolls state upward.

A blocked agent makes its pane, tab, and workspace look blocked. A working agent makes the workspace look active. A done agent stays visible until you view it.

This is the main Flockr workflow: start several agents, let them work in parallel, and use the sidebar to see which project needs a decision, which one is still running, and which one is ready to review.

## Custom agent labels

You can rename an agent target for display:

```bash
flockr agent rename w1:p1 reviewer
flockr agent rename reviewer --clear
```

Targets accept a unique live agent name or the pane ID that currently hosts the agent. Terminal IDs and bare agent-kind labels are not accepted.

You can also rename from the sidebar without the CLI. Double-click an agent row, right-click it and choose **Rename agent**, or press `prefix+shift+a` (`keys.rename_agent`) to rename the agent in the focused pane. The prompt follows the `agent.rename` rules: names match `[a-z][a-z0-9_-]{0,31}`, must be unique among live agents, and an empty name clears the alias. A renamed agent shows its alias in the sidebar instead of the reported display name. Like the CLI alias, it is kept across detach and reattach but is cleared when that agent exits or is replaced.

## Previewing an agent

Rest the mouse on an agent row in the sidebar, or press `prefix+i` (`keys.preview_agent`) for the agent in the focused pane, to see a popup with the last 15 lines of that agent's screen, its state, machine, workspace, tab and pane, and how long it has been in that state. It updates while it is open. Press `esc` (consumed), press any other key, click, or move the mouse off the row to close it.

Panes in the visible tab are read straight from the frame the client already has. Other panes on the machine you are using are fetched with the existing `pane.read` method over the client command lane every 750 ms while the preview is open. A server that does not advertise `pane.read` (an older flockr or herdr) shows "Preview unavailable" in the popup instead of failing. Agents on other connected machines show their cached state, and the popup asks you to select that machine to read its screen, because only the active machine has a command lane.

The time in state is measured by your client: the server's snapshot has a state change counter but no timestamps, so the clock starts when the client first sees the state. A state that was already running when the client attached (or when a machine first connected) is shown with a leading `≥`, for example `≥2m 05s`.

```toml
[ui.agent_preview]
enabled = true
hover_delay_ms = 600
lines = 15
```

## Custom status labels

Integrations report lifecycle state as semantic state only. Add display customization separately with pane metadata tokens.

```bash
flockr pane report-agent w1:p1 \
  --source custom:indexer \
  --agent docs-bot \
  --state working

flockr pane report-metadata w1:p1 \
  --source custom:indexer-display \
  --token summary=indexing
```

`state` controls waits, notifications, and rollups. The `summary` token is display-only and can be used as `$summary` in an Agent sidebar row.

Agent sidebar rows can also opt into `terminal_title` or `terminal_title_stripped`; neither appears in the default rows. The first shows the latest safety-normalized OSC 0/2 terminal title. The second removes one recognized leading activity or spinner glyph and following whitespace. Flockr owns these values on the server; they are ephemeral across a cold restart and remain independent of metadata titles and semantic agent state. Spinner animation can therefore update the raw title without producing a pane update when the stripped text stays the same.

## Attach directly to an agent

Attach your current terminal to one agent terminal instead of the full Flockr UI:

```bash
flockr agent attach reviewer
```

Detach with `ctrl+b q`. Send a literal `ctrl+b` with `ctrl+b ctrl+b`.

Scroll with the mouse wheel or plain page up/page down. Normal input jumps back to the bottom.

Use `--takeover` if another direct attach client already owns input:

```bash
flockr agent attach reviewer --takeover
```

Use `flockr terminal attach <terminal_id>` when you want the same direct attach behavior for a non-agent terminal.
