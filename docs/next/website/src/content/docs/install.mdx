Flockr publishes stable-channel binaries for Linux, macOS, and Windows. Windows is generally available, with documented platform-specific limitations and ongoing fixes.

## Install

On Linux or macOS, run:

```bash
curl -fsSL https://raw.githubusercontent.com/Rambarani/flockr/main/distribution/install.sh | sh
```

On Windows, run:

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/Rambarani/flockr/main/distribution/install.ps1 | iex"
```

If endpoint security blocks that fileless PowerShell command, open Command Prompt and run:

```cmd
curl.exe -fsSLo install.cmd https://raw.githubusercontent.com/Rambarani/flockr/main/distribution/install.cmd && install.cmd && del install.cmd
```

The installer downloads the release binary for your platform and places it on your PATH. New direct installs use the stable update channel. Existing Windows preview installs stay on preview until you switch them with `flockr channel set stable`. On Windows, PATH points to the active versioned release directory; the installer also updates the `current` and stable `bin` compatibility aliases, so updates do not need to overwrite a running `flockr.exe`.

## Install with Homebrew

If you already use Homebrew:

```bash
brew install flockr
```

## Install with mise

If you already use mise:

```bash
mise use -g flockr
```

If mise reports `flockr not found in mise tool registry`, update mise and retry. Older mise versions predate the Flockr registry entry; `mise use -g github:Rambarani/flockr` works as a temporary fallback.

## Install with Nix

If you already use Nix, Flockr provides a flake that builds Flockr from source:

```bash
nix run github:Rambarani/flockr/v0.x.y
nix build github:Rambarani/flockr/v0.x.y
nix profile install github:Rambarani/flockr/v0.x.y
```

Replace `v0.x.y` with the latest release tag. You can omit the tag to track `master`, but release tags are recommended for normal installs.

The flake also exposes a development shell:

```bash
nix develop github:Rambarani/flockr
```

Use the same Nix workflow to update Flockr. For a profile install, list your profile entries and upgrade the Flockr entry:

```bash
nix profile list
nix profile upgrade <index-or-name>
```

If Flockr is an input in your own flake, update that input and rebuild your system, Home Manager, or development environment:

```bash
nix flake update flockr
```

## Download manually

You can also download a binary from [GitHub releases](https://github.com/Rambarani/flockr/releases).

Choose the asset that matches your system:

| System | Asset |
| --- | --- |
| Linux x86_64 | `flockr-linux-x86_64` |
| Linux aarch64 | `flockr-linux-aarch64` |
| macOS Intel | `flockr-macos-x86_64` |
| macOS Apple silicon | `flockr-macos-aarch64` |
| Windows x86_64 | `flockr-windows-x86_64.zip` |

On Linux or macOS, make it executable and move it somewhere on your PATH.

```bash
chmod +x flockr-linux-x86_64
mv flockr-linux-x86_64 ~/.local/bin/flockr
```

### Windows archive

Stable releases and preview prereleases both include `flockr-windows-x86_64.zip`. The archive contains `flockr.exe` and its app-local ConPTY runtime. Keep the extracted directory together; do not copy only `flockr.exe`.

## Verify

Start Flockr:

```bash
flockr
```

If your shell cannot find `flockr`, restart the terminal or check that the install directory is on your PATH.

## Update

Flockr checks for new releases and notifies you in the app. You can update manually:

```bash
flockr update
```

Use `flockr update` only for installs managed by Flockr's own installer. Update Homebrew, mise, and Nix installs through those package managers instead.

Direct installs on Linux, macOS, and Windows use the stable update channel by default. To opt into preview builds from `master`, set the channel:

```bash
flockr channel set preview
```

Switch a direct install back to stable the same way:

```bash
flockr channel set stable
```

For direct installs, changing channels checks the selected channel and installs its latest binary. If that update fails, run `flockr update` to retry from the configured channel.

Preview builds are regularly published GitHub prereleases from the current development branch. They are useful when you want fixes before the next stable release, but they can regress. Homebrew, mise, and Nix installs do not use the preview channel.

Stable is the recommended channel for normal Windows use. Preview receives fixes sooner but can regress, so opt in only when you want that tradeoff. Existing Windows preview installs remain on preview until you switch them explicitly. If an older preview build rejects `flockr channel set stable`, run `flockr update` once on preview, then retry the channel switch.

By default, `flockr update` installs the new binary and leaves endpoint-generation-1 servers and their pane processes running. Start Flockr again to reconnect with the updated client. Client-only changes work immediately. A new server-side action stays unavailable until that server is updated and restarted; the client shows a notice instead of disconnecting. Servers from before endpoint generation 1 need one final stop during update.

When it finishes, `flockr update` lists any running server still on the old version with the command that restarts it, and your saved SSH machines, which run their own Flockr. Run `flockr update` on each machine to update it too.

To opt into experimental live server handoff for supported running sessions, run:

```bash
flockr update --handoff
```

When both servers support agent-status transfer, live handoff preserves hook-reported agent status until the next report arrives. Handoff from an older server can temporarily show a running agent as idle.

Live handoff does not apply to Homebrew, mise, or Nix package-manager updates. For those installs, update with the package manager, then run Flockr again to reconnect with the updated client. The compatible old server keeps running. Restart it later with `flockr server stop` or `flockr session stop <name>` only when you want server-side changes from the new release.

## Requirements

Stable-channel binaries are available for Linux, macOS, and Windows x86_64. See [Windows support](/docs/windows-beta/) for supported workflows and known limitations. Windows ARM64 runs the x86_64 build under Windows emulation.
